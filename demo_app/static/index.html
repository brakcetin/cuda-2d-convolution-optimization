What The Scores Mean

Uploaded image dimensions determine most of the convolution workload. Timing depends mainly on image size, filter size, CUDA version, block size, GPU model, and CPU/GPU transfer overhead; not on the semantic content of the image.

Kernel-only time

Measures CUDA computation after data is available on the GPU.

Total GPU time

Includes allocation, host-to-device copy, kernel, copy-back, and free time.

Memory hierarchy

Shared memory reuses input tiles; constant memory improves repeated filter reads.

Separable convolution

For box and Gaussian filters, two 1D passes reduce arithmetic work dramatically.

Small images

For 256x256 or other small inputs, CPU time can be lower than total GPU time because allocation and copy overhead can dominate.

GTX vs RTX

Raw kernel time is the fairest hardware comparison. Speedup also depends on each machine's CPU baseline.

Live Demo Expectations

What to upload

Use `data\real_images\building.png` for Sobel, `data\real_images\portrait.jpg` for Gaussian or sharpen, or `data\real_images\texture.png` for Sobel texture edges.

What output means

The output is the filtered convolution result, not a copy of the original. Sobel emphasizes edges; Gaussian blurs; sharpen increases local contrast.

Why it can look different

Edge filters produce gray/relief-like images because they show intensity changes. The building may look less visible because Sobel suppresses flat regions.

What metrics mean

Timing depends mainly on dimensions, filter size, CUDA version, block size, GPU model, and memory transfer overhead.

Why no separable Sobel?

Sobel can be implemented as smoothing plus derivative 1D passes, but this project keeps Sobel in the direct 2D group to compare memory-hierarchy kernels fairly.

Why no separable sharpen?

The canonical 3x3 sharpen kernel is not a single rank-1 separable filter. It is better treated as direct convolution here.

Run CPU Reference And CUDA On An Uploaded Image

The backend converts the uploaded image to grayscale PGM and measures exactly like the official benchmark: the single-threaded CPU reference runs 5 times, then the selected CUDA version runs 1 untimed warmup launch plus 5 timed launches (CUDA events). Reported times are averages, with min and standard deviation shown next to them, and CUDA output is compared against the CPU reference for correctness.

How To Read The Live Metrics

CPU time

Average of 5 single-threaded direct-convolution reference runs, the same CPU baseline the benchmark CSVs use. On very small images this can be lower than total GPU time.

Kernel time

Average of 5 timed CUDA launches measured with CUDA events after 1 untimed warmup launch. Min and standard deviation are shown next to the average.

Total GPU time

Allocation, host-to-device copy, kernel, device-to-host copy, and free time, averaged over the 5 repeats. For small images, overhead can dominate.

Speedup

Kernel speedup is average CPU time divided by average kernel time, exactly as in the benchmark results. For separable runs the CPU baseline is still the direct 2D convolution, so algorithmic savings count toward the speedup.
